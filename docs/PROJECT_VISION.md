# PROJECT_VISION.md

Status: Active

Version: 2.2

---

# Vision

Tutor Language is an adaptive offline Spanish tutor.

The application is not designed to teach Spanish using a fixed methodology.

Its purpose is to continuously discover how a particular learner acquires, understands, memorizes and retains Spanish most effectively.

Every completed lesson improves both:

- the learner's knowledge;
- the tutor's understanding of the learner.

The learner studies Spanish.

The tutor studies the learner.

---

# Scope

The first generation ships one complete Language Pack: Spanish.

The product experience should focus on teaching Spanish well.

The learning engine remains language-agnostic.

Language-specific educational material belongs in Language Packs.

Support for additional languages is intentionally postponed.

The project prefers an excellent Spanish tutor over an average multilingual tutor.

---

# Mission

Create a completely offline personal Spanish tutor that:

- protects user privacy;
- works without Internet access;
- requires no subscriptions;
- remains compatible with F-Droid principles;
- continuously adapts to the learner;
- improves after every lesson;
- promotes durable long-term knowledge instead of short-term performance.

---

# Core Philosophy

Every learner is unique.

There is no universal teaching strategy.

The application must continuously discover which teaching methods produce the best long-term learning outcomes for each learner.

Teaching is a continuous optimization process.

---

# Educational Philosophy

Understanding comes before memorization.

Long-term retention is more important than temporary success.

The application should:

- explain;
- demonstrate;
- ask;
- listen;
- evaluate;
- adapt;
- reinforce.

Learning should resemble working with an experienced private tutor.

---

# Memory Philosophy

The objective is durable memory.

The application should not simply repeat information.

It should continuously evaluate different memory strategies, including:

- active recall;
- contextual learning;
- storytelling;
- visual imagination;
- absurd associations;
- humorous associations;
- emotional associations;
- mnemonic techniques;
- conversations;
- spaced repetition.

The application should preserve only those strategies that demonstrably improve long-term retention for the learner.

---

# Individual Learning

Every learner develops differently.

The learner model is never considered complete.

Every lesson provides additional evidence.

The tutor continuously refines its understanding of the learner.

---

# Scientific Thinking

Every conclusion about the learner is a hypothesis.

Hypotheses become stronger only through repeated observation.

No learner characteristic should be treated as permanent.

Every conclusion remains open to revision.

The tutor must continuously verify, refine and, when necessary, reject its own assumptions.

---

# Evidence-Based Adaptation

Adaptation must always be based on measurable observations.

The application should adapt conservatively.

Insufficient evidence should never produce strong conclusions.

The application should prefer uncertainty over incorrect certainty.

---

# Learner Profile

The learner profile consists of several independent models.

## Knowledge Model

Describes what the learner currently knows.

Examples:

- vocabulary;
- grammar;
- pronunciation;
- listening;
- reading;
- writing;
- CEFR level.

---

## Learning Model

Describes how the learner studies most effectively.

Examples:

- preferred lesson duration;
- preferred exercise types;
- concentration patterns;
- learning speed;
- review behaviour;
- optimal lesson difficulty.

---

## Memory Model

Describes how long-term memory is formed.

Examples:

- forgetting patterns;
- recall success;
- effectiveness of repetition;
- effectiveness of absurd associations;
- effectiveness of visual imagination;
- effectiveness of contextual learning.

---

## Motivation Model

Describes observable learning habits.

Examples:

- preferred learning time;
- lesson completion rate;
- consistency of study;
- reaction to lesson difficulty;
- reaction to success and failure;
- signs of overload;
- signs of fatigue.

The Motivation Model exists to reduce unnecessary friction in learning.

It must never manipulate the learner.

It must never optimize engagement at the expense of education.

---

## Tutor Strategy

Determines how the application teaches this learner.

The strategy evolves throughout the lifetime of the application.

---

## Evidence Model

Tracks the strength of evidence supporting every hypothesis.

Every adaptation should be accompanied by an estimate of evidence quality.

The application should understand not only what it believes about the learner, but also why it believes it.

---

# Human Control

The learner always remains in control.

The application may:

- recommend;
- explain;
- adapt.

The learner may always override recommendations.

The tutor assists.

It never dictates.

---

# Artificial Intelligence

Artificial Intelligence is a tool.

It is not the tutor.

Its responsibilities include:

- explanations;
- conversations;
- example generation;
- optional content authoring assistance;
- optional lesson-session enhancements;
- feedback.

Teaching decisions remain under application control.

AI must never be required for lesson planning, learner modelling, review scheduling, mastery decisions, lesson assembly, lesson presentation or activity evaluation.

---

# Trust

Whenever practical, the learner should understand why a recommendation is made.

The application should avoid unexplained "black box" behaviour.

Adaptation should remain transparent whenever possible.

---

# Privacy

Learning history belongs exclusively to the learner.

Personal learning data should remain on the device whenever technically feasible.

Offline operation is the default.

---

# Learning Before Engagement

Effective education has higher priority than engagement.

Gamification is acceptable only when it demonstrably improves learning outcomes.

Entertainment must never replace education.

---

# Technical Direction

The project prefers:

- optional local AI where it adds measurable value;
- open technologies;
- modular architecture;
- deterministic behaviour whenever practical;
- maintainability;
- reproducibility;
- low hardware requirements.

---

# Development Strategy

The project evolves through small independent iterations.

Every released version must already provide practical educational value.

Avoid unnecessary rewrites.

Prefer stability over feature count.

---

# Non-Goals

The first generation is NOT intended to:

- replace professional teachers;
- support every learning methodology;
- become a social platform;
- maximize AI autonomy;
- support multiple languages;
- maximize feature count.

Its objective is singular:

Create the best adaptive offline Spanish tutor possible while preserving a language-agnostic learning engine.

---

# Definition of Success

The project succeeds when the learner studies Spanish for years and the tutor continuously becomes a better teacher for that specific learner.

The application should learn Spanish together with the learner.

It should also continuously improve its own understanding of how that learner learns best.
