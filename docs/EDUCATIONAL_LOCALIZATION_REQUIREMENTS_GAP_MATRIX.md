# Educational Localization Requirements Gap Matrix

Phase: R2E4A diagnostic audit

Status: EVIDENCE
Scope: educational content localization phase evidence
Normative authority: EDUCATIONAL_CONTENT_LOCALIZATION.md

This matrix compares the documented educational localization requirements with
the current implementation and validation behavior. It is not a translation
completion report.

| ID | Requirement | Source | Current implementation | Gap | Severity | Required action |
| --- | --- | --- | --- | --- | --- | --- |
| L10N-01 | Every localized field must have clear ownership: target-language, support-language, locale-independent, UI or technical. | `EDUCATIONAL_CONTENT_LOCALIZATION.md` classifies field ownership. | `LocalizedEducationalEntry.fields` is `Map<String, Map<String, String>>` with no per-field semantic type. | Field ownership is documented but not encoded or enforceable. | Blocker | Add semantic field type/role to inventory and localization assets. |
| L10N-02 | Target-language content must not be translated as support prose. | `CONTENT_MODEL.md`, `EDUCATIONAL_CONTENT_LOCALIZATION.md` | Generator operates on source strings and embedded fragments. | Spanish examples, names and prompt spans are not structurally separated. | Blocker | Represent target spans explicitly inside prompts/exercises. |
| L10N-03 | Support-language meanings must be natural learner-facing language. | `CONTENT_REVIEW_PROTOCOL.md:235-265` | Ukrainian generation uses exact maps, dictionary fragments and Russian-derived conversion. | Naturalness, case and agreement are not validated. | Blocker | Require review state and language-quality review for production. |
| L10N-04 | Machine/literal translation artifacts must be rejected. | `CONTENT_REVIEW_PROTOCOL.md:243-252` | Generator contains `_ukrainianFromRussian`, `_ruWordToUk`, `_translateEmbedded`, exact overrides and slash morphology. | The production candidate is generated by mechanisms that review protocol says must not be approved without review. | Blocker | Treat generator output as draft only. |
| L10N-05 | Automated tests do not replace review. | `CONTENT_REVIEW_PROTOCOL.md:36-40` | R2E3/R2E4 reports used PASS language after automated checks and smoke tests. | PASS label overstates release readiness. | Blocker | Split structural PASS from editorial/release PASS. |
| L10N-06 | Runtime fallback must not make incomplete localization appear complete. | `EDUCATIONAL_CONTENT_LOCALIZATION.md` runtime/release separation | `_field` can return requested locale or source support locale. | Renderability can hide missing/incomplete localization in smoke QA. | Major | Add release validation that forbids fallback for release locales. |
| L10N-07 | Localized pronunciation hints are support-locale content and must mark stress when required. | `EDUCATIONAL_CONTENT_LOCALIZATION.md:99-114`, `PRONUNCIATION_MODEL.md` | Ukrainian hints are often generated from Russian hints by Cyrillic substitution. | Hint language profile and independent review are absent. | Blocker | Author/review hints per support locale against IPA and policy. |
| L10N-08 | IPA, target orthography and pronunciation variety are locale-independent. | `EDUCATIONAL_CONTENT_LOCALIZATION.md:99-106` | Data stores IPA and target orthography separately. | Mostly satisfied structurally, but localized hints can contradict them. | Major | Add hint-vs-IPA/policy validation and review. |
| L10N-09 | ReadingRules are reusable target-language knowledge and localized support is separate. | `EDUCATIONAL_CONTENT_LOCALIZATION.md:126-141`, `PRONUNCIATION_MODEL.md` | ReadingRule IDs and localizations exist. | Rule applicability is not context-validated for each PronunciationUnit. | Blocker | Validate rule applicability by WritingUnit/grapheme context. |
| L10N-10 | A single-letter rule must not be applied inside a different writing unit/digraph. | Implied by `WRITING_SYSTEM_STANDARD.md` and ReadingRule/WritingUnit separation. | `Chile` references `silent_h`; explanation says the `h` is silent. | Digraph precedence is not modeled. | Blocker | Add WritingUnit/digraph-aware matching, beginning with `ch`, `ll`, `rr`, `qu`, `gu`. |
| L10N-11 | WritingUnit symbol, conventional name, reading and pronunciation must be separate. | `CONTENT_MODEL.md`, `WRITING_SYSTEM_STANDARD.md` | Standalone WritingUnit runtime schema is partial/future; localization can still infer from strings. | Symbol identity and reading behavior cannot be enforced across localization. | Major | Complete WritingUnit schema before broad production localization. |
| L10N-12 | Proper nouns/toponyms need semantic identity separate from surface text. | Required by observed content behavior; consistent with stable educational identity docs. | Pronunciation units and localization entries do not encode entity type. | Mexico/México, Chile, cities and names can be confused across meaning and pronunciation. | Blocker | Add entity metadata: person/name/city/country/exonym/pronunciation target. |
| L10N-13 | Grammar examples and mixed educational text require review. | `CONTENT_REVIEW_PROTOCOL.md` applies review to grammar explanations, prompts and examples. | Existing Ukrainian audit skips grammar example fields. | A known learner-facing area is outside automated Ukrainian checks. | Major | Audit and review grammar examples and mixed fields. |
| L10N-14 | Latin spans inside Ukrainian must be classified as intentional target-language spans, technical spans or leaks. | Target/support separation in localization docs. | Existing audit allows broad Spanish-looking words and approved Latin words. | English and malformed mixed spans can pass if not in known forbidden lists. | Major | Store span type and validate against it. |
| L10N-15 | Same English source may require different translations in different contexts. | Field ownership and review protocol. | Generator uses exact source maps and embedded replacement dictionaries. | Context-dependent translation is handled by overrides, not semantics. | Major | Translate by semantic unit, not raw source string. |
| L10N-16 | Same localized output for many source strings must be reviewable. | Review protocol naturalness/semantic equivalence. | No review metadata exists on entries. | Reused generated strings can silently collapse distinctions. | Major | Add reviewed status and reviewer notes per field. |
| L10N-17 | Pronunciation explanations must not replace or contradict IPA and rule policy. | `PRONUNCIATION_MODEL.md`, `EDUCATIONAL_CONTENT_LOCALIZATION.md` | `Chile` explanation discusses silent `h`, contradicting `ch`/IPA reality. | Learner guidance can be actively wrong while structurally valid. | Blocker | Validate explanations against referenced rules and context. |
| L10N-18 | Polish support locale should only be released after architecture supports reviewed localization. | Project support locale list includes `pl`; review protocol applies to all support languages. | Polish is listed as a support locale, but architecture defects remain. | Starting Polish now would reproduce Ukrainian defects. | Blocker | Defer Polish until this matrix's blockers are closed. |
| L10N-19 | Validation should distinguish structural, linguistic, pronunciation and release gates. | `CONTENT_REVIEW_PROTOCOL.md` stages. | Current tools report blocker counts and tests, but not editorial stage status. | Release decision lacks stage-specific evidence. | Major | Add separate reports/status fields per review stage. |
| L10N-20 | Generated localization should be traceable to source, mechanism and reviewer. | Review protocol and production accountability. | Bundle entries contain strings only. | Cannot tell whether text is authored, generated, patched or reviewed. | Major | Add provenance metadata per field and fail release on unreviewed generated text. |

## Minimum Exit Criteria For Next Phase

1. Localization asset schema contains semantic field role, span classification,
   generation provenance and review status.
2. Diagnostic architecture audit reports no blocker-level findings for
   production release candidates.
3. Ukrainian content audit covers grammar examples, prompts, mixed target/support
   spans, pronunciation support and ReadingRule support.
4. Pronunciation validation rejects rule references that are not applicable to
   the target orthography in context.
5. Release reports use stage-specific status names:
   structural PASS, automated audit PASS, editorial review PASS, production PASS.
6. Polish localization remains blocked until Ukrainian architecture blockers are
   fixed and reviewed on representative content.
